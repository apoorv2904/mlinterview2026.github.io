Two axes split the same dimension — the sequence — and share almost the same name. This chapter separates them, explains why the vocabulary is a historical accident rather than a taxonomy, and gives one test that always tells them apart.

1. Why the naming is confusing

The term was claimed twiceWho means whatWhy the names cannot help you

The confusion is not yours. Two different techniques were given the same name, four years apart, by different groups — and both names stuck.

The term was claimed twice

   2021   Li et al., Colossal-AI
          "Sequence Parallelism: Long Sequence Training from System Perspective"
          -> split the sequence across devices so long contexts fit,
             ring-style communication for attention
          -> this is what we now call CONTEXT parallelism

   2022   Korthikanti et al., NVIDIA
          "Reducing Activation Recomputation in Large Transformer Models"
          -> reused the name for something much narrower: shard the
             LayerNorm / dropout regions inside the existing TP group
          -> this is what Megatron means by SEQUENCE parallelism

   later  Megatron's usage won in practice, so NVIDIA needed a new word
          for the original meaning  ->  "context parallelism"

So the newer, narrower technique took the older, broader name, and the original idea was renamed to get out of the way. The vocabulary records who published in which order, not what the techniques do.

Who means what

When you read…from…it meanstoday’s name
"sequence parallelism"Megatron / NeMo / most 2023+ writingsharding the pointwise regions inside the TP groupSP
"sequence parallelism"Colossal-AI 2021, DeepSpeed-Ulyssessharding the sequence for long context, including attentionCP
"context parallelism"Megatron, torchtitan, most current stackssharding the sequence for long contextCP
"Ring Attention"Liu et al. 2023the algorithm a CP implementation usesCP mechanism
"Ulysses"DeepSpeedan alternative CP mechanism using all-to-allCP mechanism
⚠️ When someone says "sequence parallelism", ask which one

In a design review, a paper, or an interview, the word alone is ambiguous. The disambiguating question is short: "does attention stay sharded, or do you gather first?" Gather first → Megatron SP. Stays sharded → CP by another name. Nobody will think less of you for asking; the people who have been bitten by this ask it too.

Why the names cannot help you

Here is the deeper reason no naming scheme was ever going to work cleanly: both techniques shard the same axis. Data parallelism splits the batch, tensor parallelism splits the hidden dimension, pipeline parallelism splits the layers — each name points at a different dimension, so each name does real work. SP and CP both split tokens. The name cannot distinguish them by what they cut, because they cut the same thing.

What differs is how far through the layer the cut survives — which is a property no one-word name captures. If you want a mnemonic that holds:

   "sequence"  ->  a tensor layout detail
                   (how activations are laid out between operators)

   "context"   ->  what the model attends over
                   (the span attention has to see, so splitting it
                    changes attention itself)

2. The distinction that matters

Two kinds of regionThe side by sideThe one-line test

Two kinds of region in a transformer layer

Everything follows from a single observation: a transformer layer alternates between operators where tokens are independent and operators where tokens interact.

   ---- POINTWISE (token i depends only on token i) ----------------
        LayerNorm, dropout, residual add, GeLU/SwiGLU
        -> shard the sequence here and NOTHING changes numerically.
           Each rank computes its own tokens. No communication.

   ---- MIXING (token i depends on all tokens) ---------------------
        attention:  softmax(QK^T)V
        -> shard the sequence here and every rank is missing
           most of K and V. Communication is unavoidable.

   ---- WEIGHT MATMULS (token i independent, but needs full hidden) -
        QKV projection, MLP up/down
        -> sequence-shardable in principle; TP already splits these
           along hidden, so SP hands them the full sequence back.

Megatron’s sequence parallelism takes the first region and only the first region. Context parallelism takes the second as well — and the entire cost, complexity, and payoff of CP comes from that one extra step.

The side by side

📝 Note — they are not alternatives

SP and CP are frequently presented as a choice. They are not. SP is a strict improvement to tensor parallelism and costs nothing; CP is a separate axis you add when the context is long. A 128K-context run typically has both: TP=8 with SP on, and CP=4 on top. They shard the same dimension at different points in the layer and do not conflict.

The one-line test

   Does the technique have to move K or V between ranks?

        no   ->  sequence parallelism    (layout change, free)
        yes  ->  context parallelism     (new axis, real cost)

Section 4 of 11

3. Sequence parallelism, mechanically

What TP leaves replicatedThe operator swapWhy it is free

What TP leaves replicated

From chapter 07: between the attention block and the MLP block, tensor parallelism ends each region with g (an all_reduce), which leaves the activation replicated on every TP rank. LayerNorm and dropout then run on that full tensor, on every rank, redundantly.

   vanilla TP, per rank, per layer

   [ LayerNorm ]  full  b x s x h   on EVERY rank    <- replicated
   [ attention ]  split b x s x h/n                  <- sharded, fine
   [ LayerNorm ]  full  b x s x h   on EVERY rank    <- replicated
   [ MLP       ]  split b x s x 4h/n                 <- sharded, fine
                        ^
              at long s this replicated term dominates activation memory

The operator swap

Sequence parallelism shards those replicated regions along the sequence. The change is entirely in the f/g pair:

vanilla TPTP + SP
g (end of a block)all_reducereduce_scatter — leaves the result sharded by sequence
LayerNorm / dropouton the full sequence, replicatedon s/n tokens, once
f (start of a block)identityall_gather — re-forms the full sequence for attention/MLP
 
   TP + SP, per rank, per layer

   [ LayerNorm ]  b x s/n x h        <- sharded, no replication
        | all_gather  (f)
   [ attention ]  b x s   x h/n
        | reduce_scatter  (g)
   [ LayerNorm ]  b x s/n x h        <- sharded
        | all_gather  (f)
   [ MLP       ]  b x s   x 4h/n
        | reduce_scatter  (g)

Why it is free

This is the part worth internalizing, and it is the same identity that runs through chapters 03, 05 and 08:

   all_reduce  ==  reduce_scatter  +  all_gather
       2D                 D                D

   vanilla TP :  one all_reduce per region        = 2D
   TP + SP    :  one reduce_scatter + one all_gather = 2D

   identical bytes on the wire.

Tensor parallelism was already paying for both halves of the all-reduce; sequence parallelism simply declines to reassemble the tensor in between, and does the pointwise work while it is still in pieces. The activation memory for the LayerNorm/dropout regions drops by a factor of the TP degree, and the communication bill does not move.

⚠️ Two costs that are not zero
  • Two collectives instead of one. Same bytes, but two launches and two latencies rather than one. At small sequence lengths the latency can outweigh the memory saving, which is why SP is a flag and not the unconditional default.
  • Divisibility. seq_len must be divisible by the TP degree. A 1000-token sequence at TP=8 fails; pad to 1024.
📝 Note — the SP degree is not a free parameter

There is no --sequence-parallel-size. SP reuses the tensor-parallel group and alternates layouts within it, so the SP degree is the TP degree. It is a boolean: on or off. This is the clearest structural difference from CP, which has a real degree of its own.

4. Context parallelism and ring attention

Why a separate axisRing attentionThe online-softmax linkWhat each rank holdsOne instantThe timelineQuantified

Why a separate axis is needed at all

SP already shards the sequence. Why not simply raise the TP degree until long contexts fit?

   TP degree is capped by:
     - attention heads must divide it        (chapter 07 gotcha)
     - it wants to stay inside one NVLink domain
     - past ~8 the all-reduces stop amortizing

   and SP only shards the POINTWISE regions. Attention still sees
   the full sequence on every rank:

     attention activation ~ b x s x h/n      linear in s
     attention compute    ~ s^2              QUADRATIC in s

   at s = 128K the quadratic term wins no matter what TP does.

Context parallelism gives the sequence its own axis, so s can be divided by a degree that is not tied to head count or NVLink width.

Ring attention

Each CP rank holds a contiguous slice of the sequence — its own Q, K, V. The problem is immediate: every query must attend to every key, and most keys live elsewhere. Ring attention solves it by moving K/V rather than gathering it.

   step 0            step 1            step 2            step 3
   r0 [Q0 | K0V0]    r0 [Q0 | K3V3]    r0 [Q0 | K2V2]    r0 [Q0 | K1V1]
   r1 [Q1 | K1V1]    r1 [Q1 | K0V0]    r1 [Q1 | K3V3]    r1 [Q1 | K2V2]
   r2 [Q2 | K2V2]    r2 [Q2 | K1V1]    r2 [Q2 | K0V0]    r2 [Q2 | K3V3]
   r3 [Q3 | K3V3]    r3 [Q3 | K2V2]    r3 [Q3 | K1V1]    r3 [Q3 | K0V0]
        |                 |                 |                 |
        +-- compute partial attention, then rotate KV one hop --+

   after p steps every Q has seen every KV block.
   Q never moves. The full s x s attention matrix is never formed.

The online-softmax link

Partial results arrive one block at a time, each normalized by the wrong denominator. Combining them correctly is exactly the FlashAttention accumulation:

   per arriving KV block:
     m_new = max(m_old, max(block scores))
     s     = s * exp(m_old - m_new) + sum(exp(scores - m_new))
     out   = out * exp(m_old - m_new) + (block probs) @ V_block
                   ^
       every prior partial is rescaled when the running max moves
📝 Note — this is the genuinely online case

Chapter 07 §2 shows vocab-parallel cross-entropy doing the same numerical trick with a single all_reduce(MAX): because all the vocab tiles exist simultaneously on different ranks, one collective yields the true global maximum before any exponentiation, and no retroactive rescaling is needed.

Ring attention cannot do that. Blocks arrive sequentially, so the final maximum is unknown until the last hop, and every partial computed so far must be rescaled each time the running maximum moves. Same stabilization, but the full iterative machinery — which is why ring attention is FlashAttention’s inner loop distributed across devices rather than across SRAM tiles.

What each rank holds

Everything about the cost follows from which tensors move and which do not.

   PINNED (never moves)              ROTATING (moves every step)
   ---------------------             ---------------------------
   Q_r    this rank's queries        K_x, V_x   someone's KV block
   m_r    running row max
   l_r    running denominator
   O_r    running output
   +-- the online-softmax accumulator, one row per local query

Q never travels. That asymmetry is the design: the ring moves the smaller tensor — KV, shrunk further by GQA — past the larger, stationary one. The accumulator stays pinned because it is indexed by local query rows, which never change hands.

One instant in time

At any moment during the ring, every rank is doing three things at once, on three different pieces of hardware:

   CP = 4, during step 1

   +-- rank 0 -------------+  +-- rank 1 -------------+
   | SM   # Q0 x K3V3      |  | SM   # Q1 x K0V0      |
   | tx   -> K3V3 to r1    |  | tx   -> K0V0 to r2    |
   | rx   <- K2V2 from r3  |  | rx   <- K3V3 from r0  |
   +-----------------------+  +-----------------------+
   +-- rank 2 -------------+  +-- rank 3 -------------+
   | SM   # Q2 x K1V1      |  | SM   # Q3 x K2V2      |
   | tx   -> K1V1 to r3    |  | tx   -> K2V2 to r0    |
   | rx   <- K0V0 from r1  |  | rx   <- K1V1 from r2  |
   +-----------------------+  +-----------------------+

   computing on the block it has, forwarding that block onward,
   and pulling the next one -- SMs and copy engines / NIC run
   concurrently, which is the only reason any of this overlaps.

The timeline

  time ------------------------------------------------------------->
         step 0            step 1            step 2            step 3

  r0 SM |### Q0.K0 ######|### Q0.K3 ######|### Q0.K2 ######|### Q0.K1 ##|
     tx |K0->r1|.........|K3->r1|.........|K2->r1|.........|   (done)   |
     rx |K3<-r3|.........|K2<-r3|.........|K1<-r3|.........|            |
        +------+
         comm finishes here; the rest of the step is pure compute
        +----------- compute is the critical path throughout ----------+

  p steps of compute, p-1 rotations. Rotation k overlaps compute k.
  After p steps every Q has seen every KV block.

The bar lengths are not artistic licence — at 16K tokens per rank over NVLink the communication bar really is that short. The numbers are below.

📝 Note — double buffering, and the memory it costs

A rank cannot receive into the buffer it is currently computing on, so there are always two KV buffers in flight:

   step k     compute reads  -- buf A --   (block that arrived at step k-1)
              recv writes    -- buf B --
   step k+1   swap: compute reads B, recv writes A

That is 2 × KV_chunk of extra resident memory per rank, and it is why a CP implementation’s memory does not scale quite as 1/CP.

What it costs, quantified

   per attention layer:  p-1 hops, each moving one KV block

   bytes per hop  =  b x (s/p) x h_kv x 2 (K and V) x dtype

   NOTE h_kv, not h: with GQA or MQA the KV heads are far fewer
   than the query heads, so the ring carries much less than a
   naive reading suggests. MQA makes CP dramatically cheaper.

The important property is the shape of the two costs, because it inverts the usual intuition about communication getting harder as you scale:

   comm    per hop  ~  n           (one KV block: n x h_kv x d)
   compute per step ~  n^2         (attention over an n x n block)
                       ^
        double the chunk: comm doubles, compute QUADRUPLES

So overlap gets easier as context grows. Concretely, for a 70B-class model at 128K context, CP=8, GQA 8:1 — 16,384 tokens per rank, 64 query heads and 8 KV heads of dimension 128, bf16:

KV per hopFLOPs per stepcommcomputeratio
NVLink (900 GB/s)67.1 MB8.80 TFLOP74.6 µs12,566 µs168×
InfiniBand (50 GB/s)67.1 MB8.80 TFLOP1.34 ms12,566 µs9.4×

Setting the two equal gives the chunk size below which communication would stop hiding:

   crossover (comm time == compute time)

     NVLink       n* ~    97 tokens per rank
     InfiniBand   n* ~ 1,750 tokens per rank

   both far below any chunk anyone actually runs

Ring attention’s communication is effectively free at realistic sizes, and there is roughly 9× headroom even across nodes. It is not cheap because it moves little — it moves 67 MB per hop — but because it moves while working.

⚠️ So what actually limits CP — it is not bandwidth
  • Causal load imbalance. Every ring step is a barrier, so one slow rank stalls all of them. This is the real throughput killer and the subject of §5.
  • Buffer memory. Double buffering plus the pinned Q, m, l, O.
  • Latency at small chunk. Short context means many tiny hops, where per-hop latency rather than bandwidth dominates.
📝 Note — why CP crosses node boundaries better than TP

Tensor parallelism’s all-reduces are small, latency-bound, and sit on the critical path four times per layer with nothing to hide behind — which is why TP wants NVLink and degrades sharply outside a node. Ring attention’s transfers are large, point-to-point, and deeply overlapped with compute. That is why, when TP × CP will not fit inside one node (§6), CP is the axis to push outward, not TP.

5. The causal load-balance trap

The triangle nobody expectsThe zigzag fix

The triangle nobody expects

Ring attention with a causal mask has a load-balance problem that does not exist in the bidirectional case, and it is the detail most often missed.

Assign contiguous chunks in order — rank 0 gets the first quarter of the sequence, rank 3 the last — and the causal mask means early queries attend to almost nothing while late queries attend to almost everything:

   contiguous assignment, causal mask
   (x = must be computed, . = masked out)

           K0    K1    K2    K3        blocks computed
   Q0 r0 [  x  |  .  |  .  |  .  ]          1
   Q1 r1 [  x  |  x  |  .  |  .  ]          2
   Q2 r2 [  x  |  x  |  x  |  .  ]          3
   Q3 r3 [  x  |  x  |  x  |  x  ]          4

   rank 0 : 1 block      rank 3 : 4 blocks     -> 4x imbalance

   every ring step is a barrier, so ALL ranks run at rank 3's pace.
   three quarters of the machine waits.

The zigzag fix

Split the sequence into 2 × CP chunks instead of CP, and give each rank one chunk from the early half and one from the late half. The light chunk and the heavy chunk cancel:

   zigzag (striped) assignment, 2 x CP = 8 chunks over 4 ranks

   chunk :   s0  s1  s2  s3  s4  s5  s6  s7
   rank  :   r0  r1  r2  r3  r3  r2  r1  r0
              ^                           ^
              rank 0 takes the lightest AND the heaviest

   per-rank work becomes near-identical; the ring step no longer
   waits on one straggler.
⚠️ This is where the divisibility constraint comes from

Because the sequence is cut into 2 × CP pieces rather than CP, the requirement is seq_len % (2 × CP) == 0, not seq_len % CP == 0. At CP=4 a 128K sequence is fine; a sequence of 100,000 tokens is not. This trips people who compute the constraint from the number of ranks alone.

The animation at the top of this page shows rank 0 holding s0 and s7, rank 1 holding s1 and s6, and so on. That is the zigzag assignment, not a decorative shuffle.

6. Choosing, placing, composing

The constraint equationWhen to reach for CPRing vs UlyssesPlacement

The constraint equation

   world_size  =  TP  x  CP  x  PP  x  DP        ( x EP for MoE )

   SP does not appear: it is a boolean on the TP group.
   CP does appear: it is a real degree.

When to reach for CP

Sequence lengthReach forWhy
up to ~8KTP + SPactivations are not yet the binding constraint
8K – 32KTP + SP + selective checkpointingcheaper than adding an axis
32K – 128Kadd CPthe quadratic attention term starts to dominate
128K and beyondCP is not optionalno combination of TP/SP/checkpointing gets there

The ordering matters: exhaust the free options before adding an axis. SP costs nothing, selective activation checkpointing costs about 33% extra compute in the recomputed regions, and CP costs a ring of transfers on the critical path of every attention layer. Reach for them in that order.

Ring vs Ulysses

Ring attentionDeepSpeed-Ulysses
Mechanismrotate KV blocks around a ringall_to_all to re-shard by head for the attention, then back
Collectivepoint-to-point, p-1 hopstwo all_to_all per attention
Degree capnone in principlecapped by the number of KV heads
Overlapexcellent — each hop hides behind computeharder; the all-to-all is a barrier
Best whenvery long context, modest CP degreemoderate context, plenty of heads

Ring is the general answer and what most current stacks default to; Ulysses can win at moderate context because two large transfers beat many small ones. Some implementations combine them — Ulysses inside a node, ring across nodes.

Placement

   PLACEMENT RULE

   TP  -> inside a node, NVLink. 4 all_reduce per layer, critical path
   CP  -> inside a node if it fits, NVLink. ring transfers per
          attention layer, also on the critical path
   PP  -> across nodes. one activation per micro-batch boundary
   DP  -> outermost. one gradient reduction per step, overlappable

   TP and CP COMPETE for the same NVLink domain.
   TP=8 with CP=2 on an 8-GPU node means CP must cross nodes.
⚠️ The composition people get wrong

CP and TP shard different dimensions — CP the sequence, TP the hidden — so they compose cleanly in principle. The practical conflict is bandwidth, not correctness: both put collectives on the critical path of every layer, and a node has one NVLink domain. Chapter 09 works the placement arithmetic; the short version is that TP × CP is what has to fit inside the node, not TP alone.

📝 Note — packing interacts with CP

If you pack multiple documents into one sequence (chapter 07), the block-diagonal mask and the CP shard boundaries are independent partitions of the same axis. A document can straddle a CP boundary. Implementations handle this — varlen offsets travel with the shards — but it is worth confirming your stack does, because getting it wrong produces a model that trains without error and attends across documents.
