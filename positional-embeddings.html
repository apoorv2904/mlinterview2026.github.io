00Why any of this exists

One line of algebra motivates the entire literature. Learn to write it, because every interview on this topic opens here.

Self-attention computes softmax(QK⊤/√d)V. Permute the input rows by any permutation matrix P and every term permutes with it:

Attn(PX) = P · Attn(X)

Attention is permutation-equivariant, and the FFN and LayerNorm are applied per token, so a transformer block is too. “dog bites man” and “man bites dog” produce the same multiset of output vectors. Order has to be injected from outside.

The decoder-only caveat that catches people out

The statement above is exact for a bidirectional model. A causal mask is not permutation-invariant — token i sees exactly i+1 tokens, so the count of visible tokens is already a position signal a model can read off. This is why NoPE (section 10) trains at all rather than collapsing, and why the honest version of the claim is “a causal decoder can infer position, but not cheaply or precisely.”

≈0.1%of decode FLOPs spent on RoPE — this whole topic is free at runtime and expensive at training time

Frame the cost correctly. No positional scheme in production use is a throughput problem: RoPE is an elementwise multiply over Q and K only. What these schemes cost is generalisation — the whole design space is a trade between resolution at short range and behaviour at lengths never seen in training.

01The three-axis taxonomy

Every scheme is a point in a small grid. Place a new paper in the grid before reading it and most of its claims become predictable.

  • What is encoded: absolute position m, or relative offset m−n.
  • How it enters: added to the token vector (before WQ, WK), added to the logit (a bias on the score matrix), or applied multiplicatively to Q and K (a rotation).
  • Where it enters: once at the embedding layer, or in every attention layer.

The one-sentence history

The field moved absolute → relative (position that survives a shifted window), input-only → every-layer (position that survives depth), and additive → multiplicative (position that survives a fused attention kernel). RoPE is the point that satisfies all three at once, which is the entire reason it won — not a quality argument.

02Sinusoidal — Vaswani et al., 2017

A fixed, parameter-free vector per position, added once to the token embedding. Worth knowing properly because RoPE reuses its frequency ladder verbatim.

PE[m, 2i]   = sin( m / base^(2i/d) )
PE[m, 2i+1] = cos( m / base^(2i/d) )      base = 10000, i = 0 … d/2−1
def sinusoidal(L, d, base=10000.0):
    pos = torch.arange(L).float().unsqueeze(1)        # (L, 1)
    i   = torch.arange(0, d, 2).float()               # (d/2,)   0,2,4,…
    ang = pos * base ** (-i / d)                      # (L, d/2)
    pe  = torch.zeros(L, d)
    pe[:, 0::2] = ang.sin()
    pe[:, 1::2] = ang.cos()
    return pe                                          # x = tok_emb + pe[:L]
6.3 → 63kwavelength range in tokens, geometric across d/2 pairs — a positional binary clock

Read it as a clock. Dimension pair i has wavelength 2π·base^(2i/d), running geometrically from 2π ≈ 6.3 tokens up to 2π·10000 ≈ 62,832 tokens. Fast dims resolve neighbours; slow dims separate distant regions and are nearly constant locally. That multi-scale ladder is the actual idea, and it survives into every scheme that follows.

The property the paper was after

Because each pair is a point on a circle, shifting by k is a fixed linear map independent of m:

[PE[m+k, 2i]  ]   [ cosθk  −sinθk ] [PE[m, 2i]  ]
[PE[m+k, 2i+1]] = [ sinθk   cosθk ] [PE[m, 2i+1]]

So a linear attention head could in principle learn to attend by relative offset. Also note PE[m]·PE[n] = Σi cos(θi(m−n)) — depends only on the offset, which looks like relative encoding for free.

Why that argument is weaker than it sounds

Three holes, and being able to name them is the whole point of studying sinusoidal in 2026. One: the real logit is (xm+pm)⊤WQ⊤WK(xn+pn), and the surviving pm⊤W pn term is not a function of m−n once W is arbitrary — translation invariance is available, never enforced. Two: Σcos(θiΔ) is even in Δ, so the position term alone cannot tell before from after; direction has to come from the content cross-terms or the causal mask. Three: it is added once at the input and must survive 80 residual blocks to still mean something at the top.

03Learned absolute — BERT, GPT-2, ViT

Two lines of code, one hard wall. Included because the failure mode is the cleanest in the whole topic.

self.wpe = nn.Embedding(max_len, d)                    # d · max_len params
x = self.wte(tokens) + self.wpe(torch.arange(L))       # L ≤ max_len, or crash

Fully expressive, needs no theory, and empirically ties sinusoidal in-distribution. The cost is zero extrapolation: position max_len+1 has no row, and even interpolating rows fails because nothing forced neighbouring rows to be similar. GPT-2's 1024 is a hard architectural limit, not a tuning choice.

ViTs still use this (position is a fixed 14×14 grid, so a hard cap is free), and they interpolate the grid bilinearly when changing image resolution — the same move as position interpolation in section 07, invented independently.

04Additive relative bias: T5 and ALiBi

Stop touching the token vectors; edit the score matrix instead. One learned, one fixed, both entering at every layer.

T5 relative bias

logits[h,i,j] = q_i·k_j / √d_h  +  B[h, bucket(i−j)]

A learned scalar per head per bucket, where bucket() is exact for small offsets and logarithmic beyond, typically 32 buckets with everything past 128 tokens collapsed into the last one. T5 shares B across all layers. Cheap and effective in-distribution; past the last bucket all distances look identical, so it plateaus rather than extrapolates.

ALiBi — Press et al., 2021

2−8i/HALiBi head slopes — for H=8, exactly 1/2, 1/4 … 1/256

Delete the buckets and the parameters; use a fixed linear penalty with a per-head slope:

slopes = 2 ** (-8 * torch.arange(1, H+1) / H)        # geometric, H a power of 2
dist   = torch.arange(L)[None, :] - torch.arange(L)[:, None]   # j − i, ≤ 0 causally
bias   = slopes[:, None, None] * dist                 # (H, L, L), negative into the past
logits = q @ k.transpose(-1, -2) / d_h**0.5 + bias

No parameters, no embedding, applied every layer. Each head gets a different decay rate, so the model gets a bank of effective window sizes from ~2 tokens to ~256.

What ALiBi's extrapolation actually is

It trains at 1k and evaluates at 8k without a perplexity blow-up — but because the penalty grows without bound, tokens beyond a few thousand are simply crushed to zero weight. It generalises by becoming a soft sliding window, not by understanding long range. On long-context retrieval (needle-in-a-haystack) that is exactly the wrong inductive bias, which is why the frontier went to RoPE-plus-rescaling instead. Also note that as a logit bias it needs explicit support inside a fused kernel — FlashAttention has to be told about it, whereas RoPE happens before the kernel is ever called.

05RoPE, derived — Su et al., 2021

The one to be able to write from memory, including the two incompatible layouts that will bite you when porting weights.

The design goal, stated as an equation. Find a function f such that the logit depends on content and relative position only:

⟨ f(q, m), f(k, n) ⟩ = g(q, k, m − n)

In 2D the answer is forced: make f a rotation by an angle proportional to absolute position. Rotations compose by adding angles and the inner product is rotation-invariant, so Rmq · Rnk = q⊤Rn−mk — the absolute angles cancel and only the difference survives. For dh dimensions, stack dh/2 independent 2D rotations with the sinusoidal frequency ladder θi = base−2i/dh.

Q, K onlyV is never rotated — position belongs to the matching, not to the payload

Absolute in, relative out. This is the sentence to say out loud: each token is rotated by its own absolute index, and relativity is an emergent property of the dot product. That is what makes RoPE cacheable — you can rotate a key once, at write time, and never revisit it.

Implementation, half-split layout (HF / Llama)

def rope_tables(d_h, L, base=10000.0):
    inv = 1.0 / (base ** (torch.arange(0, d_h, 2).float() / d_h))   # (d_h/2,)
    ang = torch.outer(torch.arange(L).float(), inv)                 # (L, d_h/2)
    return ang.cos(), ang.sin()

def rotate_half(x):
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat((-x2, x1), dim=-1)

def apply_rope(x, cos, sin):                 # x: (B, H, L, d_h)
    cos = torch.cat([cos, cos], -1)[None, None]   # (1,1,L,d_h)
    sin = torch.cat([sin, sin], -1)[None, None]
    return x * cos + rotate_half(x) * sin

q = apply_rope(q, cos, sin)
k = apply_rope(k, cos, sin)                  # v untouched

Implementation, interleaved layout (paper, GPT-NeoX, GPT-J)

x1, x2 = x[..., 0::2], x[..., 1::2]          # pairs (0,1), (2,3), …
out = torch.stack([x1*cos - x2*sin,
                   x1*sin + x2*cos], dim=-1).flatten(-2)
The layout trap

Half-split pairs dim i with i + dh/2; interleaved pairs 2i with 2i+1. They are mathematically equivalent up to a fixed permutation of the head dimension, so either trains fine — but a checkpoint converted between the two without permuting WQ and WK rows produces a model that is subtly, quietly wrong. This is the single most common RoPE bug in conversion scripts. dh must also be even.

06RoPE in a real stack

Five consequences of “rotate before the kernel, every layer” that only show up in deployment.

The cache stores rotated keys

write-timeK is rotated once and cached rotated — changing θ invalidates every cached key

Standard implementations apply RoPE to k before the append to the KV cache, so the cache holds Rnkn. Consequences: (a) switching the base or the scaling factor mid-generation means re-rotating the whole cache, not a config change; (b) a cached prefix is only reusable across requests if it starts at the same absolute offset — prefix sharing works for a common prefix and not for a common middle; (c) methods that remap position indices at inference (section 07) must be applied at cache-write time or not at all.

It is free, and it is kernel-friendly

Cost is O(B·H·L·dh) elementwise on Q and K — against the O(B·H·L·dh·d) projections that produced them it rounds to nothing. More importantly it happens before the attention call, so FlashAttention needs no knowledge of it. An additive bias like ALiBi or T5 has to be plumbed into the fused kernel; that asymmetry is a large part of why RoPE dominates.

The long-term decay claim is soft

The paper argues that Σicos(θiΔ) decays with Δ. It does on average, but it is a sum of cosines and is oscillatory, not monotone — attention as a function of distance has ripples, and specific distances get anomalously boosted. Most of the 2024–25 papers in section 10 are attacks on this envelope. Do not present RoPE decay as a clean exponential.

Partial and decoupled RoPE

  • Partial rotation (GPT-J, GPT-NeoX rotary_pct, Phi): rotate only the first 25–50% of head dims, leave the rest position-agnostic. Keeps some channels free to carry pure content, and drops the slowest frequencies that were nearly constant anyway.
  • Decoupled RoPE (DeepSeek MLA): MLA's speedup comes from folding WQ⊤WK into one matrix at inference, but Rm−n sits between them and depends on the token pair, so it cannot be absorbed. The fix is structural: carry extra small head dims (64 in V2/V3) that hold RoPE, while the main compressed dims stay unrotated. When someone asks “does MLA compose with RoPE”, this is the answer — only by paying for separate dimensions.

Just raising the base

The cheapest long-context lever in existence: train with a larger base, lengthening every wavelength. Code Llama used 106, Llama 3 uses 5×105. There is a critical base below which the slowest dimension does not complete even one rotation over the target context, and positions past that point become genuinely ambiguous — which is the honest statement of why 10,000 stops working at long context.

07Context extension: PI, NTK, YaRN

The most-asked applied question in this area. All four methods are the same two-line intervention with different per-dimension weights.

The failure being fixed. A model trained to L has never seen rotation angles beyond θiL. Feed it position 4L and the fast dimensions land at angles that are out-of-distribution garbage; perplexity explodes within a few hundred tokens past the boundary. Every fix below keeps angles inside the trained range, and every one of them trades local resolution for reach. Write s = Lnew/Ltrain.

YaRN, the one worth knowing in detail

The insight: dimensions are not alike. Measure each one by how many full rotations it completes over the training window, ri = Ltrain/λi.

  • ri > 32 — fast dims, the model has seen every phase many times. Extrapolate: leave untouched, and preserve local resolution.
  • ri < 1 — slow dims that never completed a rotation. Angles past L are unseen. Interpolate: divide by s.
  • In between — linear ramp.
def yarn_inv_freq(d_h, base, L_train, s, alpha=1, beta=32):
    inv     = 1.0 / (base ** (torch.arange(0, d_h, 2).float() / d_h))
    wavelen = 2 * math.pi / inv
    r       = L_train / wavelen                          # rotations per window
    ramp    = ((r - alpha) / (beta - alpha)).clamp(0, 1) # 1 = keep, 0 = interpolate
    return inv * ramp + (inv / s) * (1 - ramp)

Second ingredient: with more tokens in the window, attention entropy drifts. YaRN corrects it by scaling the logits, implemented for free by scaling the cos/sin tables by 0.1·ln(s) + 1. Result is roughly an order of magnitude less fine-tuning data than PI for the same context.

The through-line

PI applies one factor to all dims. NTK applies a smooth power law. YaRN applies a thresholded ramp. LongRoPE searches the factors directly. It is one axis — how much per-dimension freedom you allow — and the methods are ordered along it. Llama 3.1's shipped “rope_scaling” config is a piecewise version of the same by-parts idea with a factor of 8 over an 8k original window.

09Beyond 1D: M-RoPE and friends

Once the input is an image or a video, “position” is a tuple. The generalisation is mechanical, and the interesting part is the bookkeeping.

Axial 2D RoPE. Split the head dims into two halves, rotate one half by the row index and the other by the column index. Attention then sees relative offsets in both axes. This is the standard vision-transformer form.

M-RoPE (Qwen2-VL) takes it to three: head dims are partitioned into temporal, height and width groups, each rotated by its own index. A text token sets all three indices equal, at which point M-RoPE degenerates exactly to 1D RoPE — which is what lets a pretrained LLM be adapted without discarding its positional behaviour.

Where multimodal position IDs go wrong

The hard problem is not the rotation, it is assigning indices across modalities. If a high-resolution image's spatial indices run into the range later assigned to generated text, the model cannot tell an image patch from a caption token, and the observed failure is repetition loops. Video work (VideoRoPE and the vision-language HoPE, both 2025) mostly argues about which frequency band should carry the time axis — the consensus is that time gets the low frequencies, since a video's temporal extent dwarfs its spatial one.

Name collision worth pre-empting

Three unrelated 2025 papers are called HoPE: high-frequency rotary (the ACL one above), hyperbolic rotary using Lorentz boosts for monotone decay, and a hybrid position embedding for vision-language length generalisation. Ask which one is meant before answering.

The direction of travel. Every entry above is an attack on the same two RoPE properties: the oscillatory, non-monotone distance envelope, and the under-trained low-frequency dimensions that never complete a rotation during training. If a new paper's abstract does not touch one of those, it is probably a variant of a variant.

12Cold self-test

Answer out loud before opening. Anything that needs a second attempt goes back into the deck.

Why does attention need positional information at all, stated precisely?

Attn(PX) = P·Attn(X) for any permutation P — the block is permutation-equivariant, and the per-token FFN and norm do not break it. Caveat: with a causal mask this is no longer exact, because the number of visible tokens is itself a position signal.

Write the RoPE design equation and say why a rotation is the answer.

⟨f(q,m), f(k,n)⟩ = g(q,k,m−n). Rotations compose additively in angle and preserve inner products, so rotating q by mθ and k by nθ leaves a dot product depending on (m−n)θ alone. Absolute in, relative out.

Is V rotated? Is RoPE applied once or per layer?

V is never rotated — position governs which token you match, not what you copy from it. RoPE is applied in every attention layer, unlike sinusoidal or learned absolute which enter once at the embedding.

Two implementations of RoPE disagree. What is the most likely cause?

Pairing layout. Half-split pairs i with i+dh/2; interleaved pairs 2i with 2i+1. Equivalent up to a permutation of head dims, so a converted checkpoint silently degrades unless WQ and WK rows are permuted to match.

Why does ALiBi extrapolate, and why did the field still leave it?

An unbounded linear penalty means distant tokens receive vanishing weight, so a longer sequence looks like the same soft local window — stable perplexity by refusing long range. That is the wrong bias for retrieval over long context. It also has to be plumbed into the fused attention kernel, whereas RoPE runs before the kernel is called.

PI against NTK against YaRN, in one sentence each.

PI divides every position by s, uniformly sacrificing local resolution. NTK raises the base by sd/(d−2), so fast dims barely change while slow dims interpolate. YaRN partitions dims by rotations-per-training-window and applies a ramp between α=1 and β=32, plus a logit temperature. One axis: how much per-dimension freedom you allow.

Which dimensions actually need interpolation, and why?

The slow ones. A dimension that completed dozens of rotations during training has seen every phase, so unseen positions land on familiar angles — it can extrapolate. A dimension whose wavelength exceeds the training window never completed a rotation, so any longer position is a genuinely unseen angle. Note the partition is set by the training window and base, not by the target length.

Why can't MLA absorb RoPE, and what is the fix?

MLA's inference speedup folds WQ⊤WK into a single matrix, but Rm−n sits between them and varies per token pair, so the product cannot be precomputed. DeepSeek's fix is decoupled RoPE: extra dedicated head dimensions (64) that carry the rotation while the compressed latent dims stay unrotated.

You switch RoPE scaling mid-generation. What breaks?

The KV cache. Keys are stored already rotated, so every cached key is at the old angles. Any change to base, scale, or position mapping requires re-rotating the entire cache — a real cost that makes dynamic-NTK-style per-step rescaling awkward in a serving system.

What is the shared target of HoPE, FoPE and most 2025 RoPE papers?

Two defects: the distance envelope Σcos(θiΔ) is oscillatory rather than monotone, and the low-frequency dimensions are under-trained because they never complete a rotation. HoPE drops the low frequencies; FoPE reshapes each dimension into a Fourier series. Same defect, opposite fixes.

If the design equation, the ri = Ltrain/λi partition, and the cache consequence all come out without reaching back to this page, the material is yours.

13Traps

Errors that survive a confident explanation, which makes them the dangerous ones.

  • Saying “RoPE is a relative encoding” and stopping. It applies an absolute rotation per token; relativity emerges in the dot product. The distinction is the entire reason keys can be cached rotated, and interviewers probe exactly there.
  • Rotating V. Only Q and K. If you rotate V the output picks up a position-dependent spin that nothing removes.
  • Claiming sinusoidal gives relative attention for free. The pm⊤WQ⊤WKpn term is only translation-invariant for special W. It is available to be learned, not enforced — that gap is why RoPE exists.
  • Treating RoPE decay as monotone. It is a sum of cosines with ripples. Half the 2025 literature is about that envelope.
  • Confusing the two RoPE layouts. Half-split and interleaved differ by a permutation of head dims. Converting a checkpoint without permuting WQ/WK gives a model that loads, runs, and is quietly worse.
  • Interpolating every dimension. That is PI, and it costs local resolution proportional to s. The fast dims never needed it — they had already seen every phase.
  • Assuming the YaRN split moves with the target length. It is fixed by Ltrain and the base. Only the scale applied to the interpolated band depends on s.
  • Forgetting the cache is rotated. Every inference-time position remap has to happen at cache-write time, and re-scaling mid-stream is not a config toggle.
  • Quoting ALiBi's extrapolation as long-range ability. It extrapolates by becoming local. Say “stable perplexity, not preserved retrieval.”
  • Assuming a bias-based scheme is kernel-free. Additive biases must be supported inside the fused attention kernel; RoPE runs before it. That engineering asymmetry decided the winner more than quality did.
  • Bumping the base without fine-tuning and expecting the old short-context behaviour. Every wavelength moves, including the ones doing local work.
  • Saying NoPE proves position encoding is unnecessary. It holds for causal decoders, largely at small scale, and production use is hybrid — NoPE on global layers with RoPE kept on local ones.
