00The hardware, in one paragraph

You need exactly two facts about the GPU. Every result below is a consequence of one of them.

~100×bandwidth gap, SRAM over HBM

There are two memories. HBM is large and slow — 40–80 GB at roughly 1.5–3 TB/s. SRAM is tiny and fast — about 192 KB per streaming multiprocessor on A100, at roughly 19 TB/s. Anything that does not fit in SRAM lives in HBM, and every trip to HBM is expensive. Call the SRAM capacity M, measured in elements: for bf16 at 2 bytes each, 192 KB is about 105 elements.

16×cost of a non-matmul FLOP vs a matmul FLOP

There are two kinds of arithmetic. Matmuls run on tensor cores at 312 TFLOP/s (A100, bf16). Everything else — exp, divide, add, compare — runs on general FP32 units at about 19.5 TFLOP/s. A non-matmul FLOP therefore costs roughly 16× a matmul FLOP. This is why softmax, which is nothing in the FLOP count, is a real fraction of the runtime.

01Vanilla attention: three separate quantities

FLOPs, bytes, and retained memory are three different questions. Answer them separately — most wrong answers collapse them into one “complexity”.

Stage by stage

StageFLOPsHBM trafficNote
S = QKT2N²dread 2Nd, write N²V not needed yet
P = softmax(S)~2N²read N², write N²cheap FLOPs, expensive bytes
O = PV2N²dread N² + Nd, write Nd
Θ(N²)activation memory retained, per head per layer

Totals. FLOPs are Θ(N²d), precisely 4N²d forward. HBM traffic is Θ(N² + Nd), dominated by the N² round-trips. Activation memory retained for the backward is Θ(N²) per head per layer — the P matrix.

The trap

Traffic is Θ(N² + Nd), not Θ(Nd). The figure 3Nd read plus Nd written is what an ideal fused kernel moves — it answers “what does the math need”, not “what does the kernel actually write out”.

The N² term exists purely because the stages are separate kernel launches. Each must write its result to HBM so the next can read it. Nothing about the mathematics requires this.

Self-check: if traffic really were Θ(Nd), fusion would have nothing to save. If your answer to “what does Flash change” contradicts your traffic estimate, the traffic estimate is wrong.

02What FlashAttention changes — and doesn't

The second list is where marks are lost.

Changes

  • Fuses the three stages into one kernel, so S and P never touch HBM
  • Tiles the computation so each block's working set fits in SRAM
  • Online softmax — computes the normaliser incrementally instead of needing a full row up front
  • Recomputes S in the backward instead of storing it
  • Traffic drops from Θ(N²) to Θ(N²d²/M)
  • Activation memory drops from Θ(N²) to Θ(Nd + N)

Doesn't change

+25%backward FLOPs vs standard — it does more arithmetic, not less
  1. It is exact. Bit-for-bit the same function, modulo floating-point reassociation. Not an approximation. This matters because it sits in a literature full of Linformer / Performer / Reformer-style approximations that trade accuracy for speed. Flash trades nothing.
  2. It does not reduce FLOPs — it increases them. Rescaling in the forward, recomputation in the backward. It does more arithmetic and wins anyway.
  3. Time complexity is still Θ(N²d). It is a constant-factor IO win, not an asymptotic one. Next to the linear-attention family, this is the single most important distinction to state.
  4. It is not universally better. When d² > M, it moves more traffic than standard attention. See section 04.
Say both halves

Saying only “it's exact” states the easy half — that's the part everyone knows. The pair — exact, and it does more FLOPs — is the answer.

03Why attention is memory-bound

Arithmetic intensity is FLOPs per byte of HBM traffic. Below the machine's own ratio you wait on memory; above it you wait on arithmetic.

Units discipline

Intensity is FLOPs per byte. Everywhere else in these notes traffic is counted in elements, so the conversion must be done explicitly. This is the one place a factor of 2 silently changes the answer.

Step 1 — count elements. The N×N matrix crosses the bus four times: write S, read S, write P, read P.

4 × N² = 4N² elements

Step 2 — convert to bytes. bf16 is 2 bytes per number.

4N² elements × 2 B = 8N² bytes

Dropping the Θ(Nd) terms — reading Q, K, V and writing O, another 8Nd bytes — since N >> d.

d/2attention intensity — about 32 FLOPs/byte at d=64

Step 3 — divide into the FLOPs.

intensity ≈ 4N²d / 8N² = d/2 ≈ 32 FLOPs/byte at d=64

In fp32 the crossings cost 16N² bytes and intensity halves to d/4. The precision is part of the answer, not a detail.

attention, d=64~32
A100 balance~150
H100 balance~300

Five to ten times under. The tensor cores sit idle most of the time, waiting on HBM.

Per-element intuition

Divide both sides by N² and ask what happens to one score entry over its lifetime. It participates in 4d FLOPs — a d-length dot product to produce it, then d multiply-adds to consume it — and costs 8 bytes to move. Ratio: 4d/8 = d/2.

The structural reason is that QKT is a matmul with a tiny reduction dimension and an enormous output. Each output element costs 2d FLOPs and 2 bytes to write, so the moment you materialise it, intensity is capped near d no matter what else you do.

The insight worth keeping

Intensity is Θ(d) — independent of N. Both work and traffic scale as N², so nothing amortises: every new score entry brings its own fixed 4d FLOPs and its own fixed 8 bytes. Longer sequences never help. Only wider heads do, and you would need d >rsim 300 to reach machine balance.

This is also the diagnostic to reach for on any kernel: compute FLOPs per byte, compare to 150–300, and you immediately know whether fusing is worth it.

04The IO derivation

The headline result. Derive it, don't memorise it.

Setup

Split K, V into T_c = ⌈N/B_c⌉ blocks of shape B_c × d. Split Q into T_r = ⌈N/B_r⌉ blocks of shape B_r × d.

Why M enters

For one inner step to run entirely on-chip, its whole working set must be resident simultaneously.

ResidentSize
Q_iB_r·d
K_j, V_j2B_c·d
O_i accumulatorB_r·d
S_ij score tileB_r·B_c
m_i, l_i2B_r (negligible)
 
(2B_r + 2B_c)·d + B_r·B_c ≤ M

The d dimension is never tiled — it is small enough to hold whole, and it is the reduction axis for both matmuls, so splitting it would force partial-sum spills.

Block sizes that fall out

B_c = Θ(M/d)B_r = min(Θ(M/d), d), so B_r = Θ(d) in practice

The B_c·d term forces B_c = Θ(M/d). Then B_r·B_c ≤ M forces B_r = min(Θ(M/d), d), and since M >> d² in practice, B_r = Θ(d). Real kernels use 64 or 128, chosen for tensor-core tile shapes and register pressure — the bound gives the scaling law, not the constant.

The counting argument

FlashAttention-1 loop order, K/V outer, Q inner:

for j in 1..T_c:              # K/V blocks
    load K_j, V_j             # each loaded exactly once
    for i in 1..T_r:          # Q blocks
        load Q_i, O_i, m_i, l_i
        compute S_ij, update O_i, m_i, l_i on-chip
        store O_i, m_i, l_i
  • K, V are loaded once each across the whole outer loop → 2Nd total.
  • Q and O are the cost. Every outer pass sweeps all query blocks, because every query row needs the contribution from K_j. So each of the T_c passes reads all of Q and read-modify-writes all of O.
Θ(N²d²/M)FlashAttention HBM traffic — the headline result
traffic = 2Nd + T_c · Θ(Nd)
        = Θ(N²d / B_c)
        = Θ(N²d²/M)

The N×N score matrix never touches HBM. What does cross the bus repeatedly is Q and O — that is the price of tiling. Bigger SRAM means bigger B_c, fewer passes, less re-reading. That is the entire role of M.

The win, and where it flips

standard / flash = N² / (N²d²/M) = M/d²
Speedup M/d² at head dim 23×
d 64
32128256384512

Comfortably worth it. Traffic drops by more than an order of magnitude.

The win decays quadratically in head dimension, with break-even near d ≈ 310 for M ≈ 105. Head dims stayed at 64–128 as models grew partly for this reason.

Two things worth having

Why M/d and not √M. Classic blocked matmul is Θ(n³/√M) — you tile all three loops, so each tile edge is √M. Attention tiles only two, holding d whole, so the savings factor is the full M/d. Attention gets a better exponent than matmul precisely because one dimension is small enough to stay resident.

It is optimal. The paper proves a matching lower bound Ω(N²d²/M) for M in [d, Nd]. No exact attention algorithm does asymptotically better in this memory model. Everything since is constant-factor.

05Online softmax

Three running values per query row: max, normaliser, output accumulator.

On arrival of block j with scores S_cur:

m_i = max(m_{i-1}, rowmax(S_cur))

l_i = e^(m_{i-1} - m_i) · l_{i-1}  +  Σ e^(S_cur - m_i)

O_i = e^(m_{i-1} - m_i) · O_{i-1}  +  e^(S_cur - m_i) · V_j

finally:  O ← O / l
logit > 11fp16 overflow threshold, ln(65504) — well inside normal range

Where the max enters, and what breaks without it

Every exponential is taken relative to the current max m_i — never the raw score, never the old max.

  • Both the carried term and the new term rebase to m_i. Rebasing the new block's term to m_{i-1} is a real bug: the accumulators go inconsistent, and e^(S - m_{i-1}) overflows whenever the new block holds a larger score.
  • It is a nasty bug class — silent, and invisible on any test where blocks happen to have similar maxima.
FA1 vs FA2 form

FA1 applies diag(l)-1 at every inner step. FA2 carries O unnormalised and divides once at the end — fewer non-matmul FLOPs, see section 07. This is the better formulation.

06Backward pass

Spend matmul FLOPs, save HBM bytes. The trade is quantifiable on both sides.

FLOP accounting

Each N×N×d contraction is 2N²d.

PassMatmulsFLOPs
ForwardQKT, PV4N²d
Standard backwarddV = PTdO, dP = dO VT, dQ = dS K, dK = dSTQ8N²d
Recompute Sone extra QKT+2N²d

10N²d against 8N²d — +25% backward FLOPs, about +17% per training step (14N²d vs 12N²d). The backward is naturally twice the forward; that ratio holds for essentially every matmul-heavy layer.

Why it is still faster

For N=8192, d=64, one head, bf16, A100:

  • recompute cost: 2N²d = 8.6 GFLOP ÷ 312 TFLOP/s → ~28 µs
  • bytes avoided: reading P alone = 134 MB ÷ ~2 TB/s → ~67 µs

About 2.4× in favour of recomputing, counting only one read of P. The standard backward also writes dP and reads it back for dS, so the real win is larger. The general rule: recomputation pays whenever the recompute's arithmetic intensity exceeds machine balance, and a tile of QKT regenerated in SRAM has effectively infinite intensity because it never crosses the bus.

The reason that actually matters

137 GB → 17 MBactivations for a 32-layer, 32-head model at N=8192, bf16

Speed is the smaller half. Storing P is Θ(N²) per head per layer:

8192² × 2 B × 32 layers × 32 heads ≈ 137 GB

That fits on nothing. Flash stores Θ(Nd + N) instead — about 17 MB, a roughly 8000× reduction. Long-context training is not slower without this; it is impossible. When people say FlashAttention enabled long context, this is the mechanism, not the kernel fusion.

What is saved from forward

Only two things beyond Q, K, V, which are retained anyway as layer inputs.

L = m + log l, the merged logsumexp:

P_ij = e^(S_ij - m_i) / l_i = e^(S_ij - m_i - log l_i) = e^(S_ij - L_i)

Softmax normally needs two passes — find the max, then normalise. With L_i in hand it is a single fused exp. One vector of N floats replaces an N² matrix. FA1 stored m and l separately; merging them is an FA2 refinement.

O, the forward output, retained for the softmax backward.

The identity that makes it tile

From the softmax Jacobian, dS_ij = P_ij (dP_ij - Σ_k P_ik dP_ik). That row-sum couples every column, which is fatal for a tiled kernel. But dP_ik = dO_i · V_k, so:

Σ_k P_ik dP_ik = Σ_k P_ik (dO_i · V_k)
                  = dO_i · (Σ_k P_ik V_k)
                  = dO_i · O_i

D_i = rowsum(dO ∘ O)      dS = P ∘ (dP - D)

Global coupling collapses to one scalar per row, computable in a Θ(Nd) pass before the main loop. Without this, no tiling scheme works at all — recompute or not — because every tile would need its row's full normaliser.

The loop

S_ij  = Q_i K_j^T
P_ij  = e^(S_ij - L_i)
dV_j += P_ij^T dO_i
dP_ij = dO_i V_j^T
dS_ij = P_ij ∘ (dP_ij - D_i)
dQ_i += dS_ij K_j
dK_j += dS_ij^T Q_i

Loop order: K/V outer, Q inner — flipped relative to FA2's forward. Two of the three outputs, dK_j and dV_j, accumulate over query blocks, so K/V outer keeps them in registers. dQ is the one that loses: it accumulates over j, needing atomic adds or a split-and-reduce. You cannot win on all three; the kernel picks the two worth more.

Not the same as gradient checkpointing

Generic checkpointing recomputes a whole block and still materialises N² transiently during the recompute. Flash's is selective: it targets the one tensor that is cheap to regenerate and ruinous to store, and regenerates it tile-local, so the N×N matrix never exists in HBM in either direction.

07FA2 and the non-matmul tax

Once the N² traffic is gone, the remaining inefficiency is cheap FLOPs running on slow units.

The loop swap

FA1:  for j in 1..T_c:          FA2:  for i in 1..T_r:
        load K_j, V_j                 load Q_i; O_i in registers
        for i in 1..T_r:              for j in 1..T_c:
          load Q_i, O_i  ← HBM         load K_j, V_j
          update                        update O_i  ← registers
          store O_i      ← HBM     O_i ← O_i/l_i; store once

Recount: Q and O are now touched once each, and K, V become the re-read tensors → T_r · 2Nd = 2N²d/B_r. The constraint mirrors too, with B_r = Θ(M/d) and B_c ≤ d. Same Θ(N²d²/M) — the derivation is symmetric under the swap, only the identity of the victim changes.

So why swap

~2×FA2 over FA1 — 50 to 73% of peak matmul throughput
  1. The accumulator stops round-tripping. In FA1, updates to a given O_i land in different outer iterations, so it must be evicted and reloaded between them. In FA2 they are consecutive and O_i never leaves registers — the worst kind of traffic, read-modify-write, is eliminated.
  2. Parallelism over query blocks. The big one. FA1 parallelises over batch × heads only, which at long context with small batch is too few thread blocks to fill 108 SMs. Why query and not key: query blocks partition the output, key blocks do not. Two query blocks write disjoint rows of O with zero communication; two key blocks both contribute to every row, needing atomics or a reduction pass.
  3. Fewer non-matmul FLOPs. The unnormalised accumulator — divide once per query block, not once per inner step.
  4. Warp-level split-Q. Same partition-the-output logic one level down: warps own whole rows, share K/V tiles, no cross-warp reduction.

Bonus: causal masking gets clean. With Q outer, block i only needs j ≤ i, so you skip half the inner iterations outright instead of computing and masking.

The non-matmul tax

0.4% / 6%share of backward FLOPs vs share of backward runtime, for dS

dS = P ∘ (dP - D) is 2N² elementwise FLOPs — about 1/(4d) ≈ 0.4% of the backward's matmul work. Negligible arithmetically. Now apply the 16× rate penalty:

time fraction = (2N²/19.5) / (8N²d/312) = 4/d ≈ 6% at d=64

0.4% of the FLOPs, about 6% of the time. Never call FLOPs negligible without checking which units they execute on.

OpFLOPsUnit
D = rowsum(dO ∘ O)2NdFP32 — truly negligible, Θ(Nd)
P = exp(S - L)~2N²subtract FP32, exp on SFU
dS = P ∘ (dP - D)2N²FP32

Θ(N²) non-matmul against Θ(N²d) matmul — the same 1/d structure, amplified 16× or worse. MUFU.EX2 issues at roughly a quarter of FP32 rate, stacking penalties. Realistically, softmax work is 10–20% of a tuned kernel's runtime at d=64, despite being under 1% of its FLOPs.

Traffic cost of dS: zero. dP_ij is a B_r × B_c register tile and dS_ij overwrites it in place. Subtracting D_i broadcasts along the row, register-local under split-Q. Second payoff of the rowsum(dO ∘ O) identity: the correction is not just tileable but free in memory terms.

The arc

FA1 fixed memory traffic. FA2 fixed non-matmul FLOPs and parallelism. FA3 on Hopper hides the remainder — warp specialisation with async TMA copies, and pingpong scheduling that overlaps one block's softmax with the next block's matmul. Same FLOPs, better occupancy. Still Θ(N²d²/M).

Each attacked whatever became the bottleneck after the previous fix. That is how kernel optimisation usually goes — you do not pick the bottleneck, you inherit it.

09Self-test

Cold, no notes. Answer aloud before opening each one.

State the three L1 quantities separately. Where does the N² in traffic come from, and why is it not Θ(Nd)?

FLOPs 4N²d; traffic Θ(N² + Nd); retained activation Θ(N²). The N² comes from four bus crossings of the score matrix across three separate kernel launches. Θ(Nd) is what an ideal fused kernel would move, not what the standard implementation actually writes.

Derive Θ(N²d²/M) from the SRAM constraint. Then plug in d = 64, 128, 256 and find the crossover.

Working set (2B_r + 2B_c)d + B_r B_c ≤ M gives B_c = Θ(M/d). Each of the T_c = N/B_c outer passes re-reads all of Q and O, so traffic is N²d/B_c = N²d²/M. Speedup M/d²: ~23×, ~6×, ~1.5×, break-even near d = 310.

Write the online-softmax recurrence. Which term overflows if you rebase the new block to m_{i-1}, and at what logit value in fp16?

The new block's own term, e^(S_cur - m_{i-1}), whenever that block contains a larger score than any seen so far. fp16 overflows above ln(65504) ≈ 11.

Compute attention's arithmetic intensity and say why it does not improve with longer sequences.

4N²d / 8N² = d/2. Both work and traffic scale as N², so N cancels — every extra score entry brings its own fixed 4d FLOPs and its own fixed 8 bytes. Nothing amortises.

Show Σ_k P_ik dP_ik = dO_i · O_i, and say what breaks in the backward without it.

Substitute dP_ik = dO_i · V_k and pull dO_i out of the sum; what remains is Σ_k P_ik V_k = O_i. Without it the softmax backward needs a full-row reduction over dP, so no tile can compute its own dS and the whole tiling scheme fails — independently of recomputation.

Name two things FlashAttention does not do, and one regime where it is worse than standard attention.

It does not reduce FLOPs (it increases them) and it does not change the Θ(N²d) time complexity. It is worse when d² > M, i.e. head dims beyond roughly 310 for A100-class SRAM.

If question 2 and the M/d² ratio fall out without reaching back to these notes, the material is yours.

10Common traps

  • Quoting Θ(Nd) traffic — that is the ideal fused number, not what the kernel writes
  • Collapsing FLOPs, bytes and retained memory into one “complexity”
  • AV is N²d, not Nd²
  • Saying “it's exact” without adding “and it does more FLOPs”
  • Forgetting that time complexity stays quadratic — it is an IO win, not an asymptotic one
  • Assuming it is universally better; it fails at d² > M
  • Rebasing the new block's exponential to the old max
  • Calling Θ(N²) non-matmul work negligible because it is under 1% of FLOPs
  • Counting elements where the question asks for bytes
